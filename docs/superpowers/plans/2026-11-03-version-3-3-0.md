# 3.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Version 3.3.0: a highlighted row says who it waits for and why, a pull request whose title names no Jira key takes the keys of its source branch, and each card links the other pull requests of its issues ("(see 12, 45)") with their preview and a scroll-to icon.

**Architecture:** The branch keys are read where the title keys are (`createJiraIssuesMap`, project-assembly.mjs, shared by the server and the fixture generator). The reason comes from the attention rule (app-filter.js), whose conditions become one "who waits" function per kind of row; the filter pass writes it on an icon every row carries. The related lists are rendered from the issue map (app-render.js); their previews read the target row's own data attributes, and app.js hands the popovers `isShown` and `reveal`, with the unfold in tree-toggle.js.

**Tech Stack:** Node.js 20.11+ (ES modules), vanilla ES modules in `public/`, `node:test`, Font Awesome 5.15.3 (vendored).

**Spec:** `docs/superpowers/specs/2026-11-03-version-3-3-0-design.md`

## Global Constraints

- Every Bitbucket and Jira text interpolated into HTML goes through `escapeHtml` (`public/escape-html.js`); repository names and reasons set on the DOM go through `textContent` / `setAttribute`, never `innerHTML`. Bitbucket's rendered title and description are the only HTML shown as HTML.
- No inline handler, no `style=` attribute, no `<style>` (CSP, security-headers.mjs). Styles in styles.css, colours as tokens only (`--attention-strong`, `--primary-color`, `--border-color`, ...), never a literal colour.
- Every `<i>` in the tree is `aria-hidden="true"` or `role="img"` with a non-empty `aria-label` (test/app-render.test.mjs). Never `outline: none`.
- app-render.js knows no filter state; nothing goes on `window`; frontend modules touch no DOM at import time.
- A pull request is known by `pullRequestKey` ("destination repository/id", `public/pull-request-key.mjs`), never by its id alone.
- Folds go through `setRepositoryCollapsed`, `setRootBranchCollapsed`, `setPullRequestCollapsed` (tree-toggle.js); a selection by the user through app.js's `selectRow`.
- The filter pass stays around a millisecond on SECOLLAB in fixture mode; it reads nothing from the DOM to decide (pitfall 6) and writes an attribute only when its value changes.
- The reason strings, exactly: prefix `Waiting for `, `name: role[, role]`, people joined by ` · `; roles `review`, `issue in progress`, `1 open task` / `N open tasks`, `approval`, `nobody left to approve`; the label before the first pass `Waiting for a selected participant`.
- Icons: `fa-hourglass-half` (reason), `fa-crosshairs` (scroll to).
- CRLF files (`.gitignore`, `package-lock.json`, `cache.mjs`, `index.mjs`, `public/multi-select.js`): edit them keeping CRLF.
- Commit messages `type: description`, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Branch `claude/3-3-0`.
